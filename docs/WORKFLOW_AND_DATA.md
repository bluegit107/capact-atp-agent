# WORKFLOW & DATA — S4 협상 루프와 저장

## 흐름
`open`(가정 AS-001~005, AS-001 결정 불변성 게이트 평가) → `plan_inquiries`(프로브 가치 순으로 레버·문의·작업 생성) → `send` → `receive`(주제별 효과 → 재풀이·게이트 재평가·확정 계획 낡음 표시) → `accept_counter`(레버 담당만, 손익분기 초과 시 거부) / `advance_clock`(기한 경과 → 만료·작업 막힘) / `reask` → `submit`(게이트) → `decide`(권한표 승인 주체만) → `promote_plan`(승인된 레버만으로 재풀이·일치 확인 후 Plan of Record) / `change_conditions`(환율·단가·회수 의결 → 재검증).
구현: `application/negotiation.py`(유스케이스), `domain/workspace.py`(상태), `adapters/demo_cases.py`(필수 3케이스), `scripts/run_cases.py`(증거 생성).

## 상신·승인·확정 규칙
- **상신 게이트**: AS-001(항상) · AS-004(부분 수락이면) · AS-005(OPT-02 사용이면)가 미확정이면 차단. 실행 불가능하거나 **기준 대비 증분 순이익이 음수**면 차단(영업임원·CEO/이사회만 `accept_loss`로 진행 가능). 차단 작업은 안별 하나로 갱신.
- **승인 요청** = 시나리오 필요 승인 + **실제로 쓰인** 레버의 승인(외주·특근·양해는 B처럼 양해를 쓰는 안에서만). 승인 주체는 권한표(정책 버전 고정).
- **승인은 그 상신 건에만 유효**: 상신 시 승인 ID 목록과 입력 해시를 기록. 확정 시 입력 해시가 다르면 "재상신 필요", 이전 상신의 승인은 쓰지 않는다(테스트가 실제 결함을 잡아 도입).
- **확정**: 승인된 레버만으로 다시 풀어 상신안과 수락률이 1%p 안이면 `promote()` → Plan of Record 버전 증가, 사용 레버 APPLIED. 이후 조건이 바뀌면 `plan_stale` + 재검토 작업.
- **CEO 투자 거절** → 해당 옵션 제외(`excluded_options`) 후 대안 재계산·재상신.
- 기준 계획(Z)도 추가 능력(옵션·외주·특근)을 쓸 수 있다 → 추가 능력은 기존 약속이 먼저 쓴다(W05 "매출 기회보다 먼저 확인할 공급 약속").

## 저장(AXHub PostgreSQL)·보안 (`adapters/repo_postgres.py`)
- 워크스페이스 상태를 **AES-256-GCM** 앱 단 암호화(키: `CAPACT_DATA_KEY` 환경변수, DB에 키 없음, 키 ID 기록). AAD = `workspace_id|version` + 복호화 후 ID·버전 대조(이중 방어). 키 없이 저장 시도는 거부(개발용 `allow_plaintext` 명시 필요).
- **낙관적 락**: `UPDATE … WHERE version = 기대값` → 실패 시 `ConcurrencyConflict`.
- **감사**: `audit_events` 추가 전용(UPDATE·DELETE·TRUNCATE 트리거 거부), ID·해시만 저장.
- **마이그레이션**: 버전 테이블 + advisory lock, 재실행 무해. 풀러 호환(`prepare_threshold=None`), 운영에서는 `DIRECT_DATABASE_URL`로 마이그레이션.
- 메모리 저장소와 **같은 계약 테스트**를 통과(라운드트립·락·감사 순서).
- 로컬 검증: 내장 PostgreSQL 16(스크래치패드, 포트 54329, `CAPACT_TEST_PG_URL`). 설치 경로에 한글이 있으면 initdb가 실패해 영문 경로로 복사해 실행했다.
